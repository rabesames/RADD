# ADR-0036: Lexical CEL checks in lint until the CEL library is chosen

- Status: Accepted
- Date: 2026-10-26
- Deciders: Rommel

## Context

Lint must check CEL expressions (the declared subset, custom-function references), but the TypeScript CEL library is chosen in stage 2. Stage 1 still needs to catch typos in function names and use of extensions that are not enabled.

## Decision

- Stage 1 lint uses a small CEL lexer (`packages/core/src/cel.ts`) that reports lexical errors (unterminated strings, unbalanced brackets; RADD701) and finds function calls.
- Each call is checked against standard CEL functions and macros, the RADD built-ins, the functions in `functions.yaml` (RADD207) and the functions of the CEL extensions listed in `dictionary.yaml` (RADD208). A dotted call `a.b(...)` is a namespaced function when `a` is a known namespace, and otherwise a member call `b` on the value `a`.
- Identifier resolution, type checking and the decimal-arithmetic warning wait for the stage 2 library, which replaces the lexer.

## Alternatives considered

- **No expression checks until stage 2.** Typos in function names would pass lint.
- **Write a CEL parser now.** Duplicates the library that stage 2 will pick.

## Consequences

- Unknown field names in expressions are not caught in stage 1.
- The lexer's function lists must match what the stage 2 libraries support, and are replaced with them.
