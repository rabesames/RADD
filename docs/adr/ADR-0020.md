# ADR-0020: Distribute from the git repository now, NuGet and npm later, with a one-command initializer

- Status: Accepted
- Date: 2026-10-26
- Deciders: Rommel

## Context

Publishing packages commits to names, versions and support early, while the framework is still changing every stage. Adopters still need an easy way to start a project.

## Decision

- **Now:** projects consume the framework from this repository, through .NET project references and npm workspace or file links.
- **Later:** the .NET packages are published to NuGet and `@radd/client` to npm, all under the same version number.
- `radd init <name>` creates a working project with every layer (a `/dictionary` folder with a sample entity, lookup and locale; an ASP.NET Core API with EF Core on SQLite; a React + TypeScript app using `@radd/client`; AGENTS.md; CI lint and conformance steps). It checks for the .NET SDK and Node first, uses `dotnet new` and npm, points both at the git repository until packages are published, and keeps working unchanged once they are.

## Alternatives considered

- **Publish packages from the start.** Premature commitments and package-name squatting risk while the API changes every stage.
- **No initializer.** Every adopter wires the layers by hand.

## Consequences

- Package names must be checked for availability before publishing (ADR-0017).
- The initializer has to support both sources.
