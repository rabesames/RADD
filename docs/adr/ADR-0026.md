# ADR-0026: Dictionary folder layout, YAML 1.2 and the YAML features RADD allows

- Status: Accepted
- Date: 2026-10-26
- Deciders: Rommel

## Context

ADR-0002 makes the dictionary a folder of YAML files. YAML has dialect differences (1.1 turns `N`, `no` and `on` into booleans) and features (anchors, aliases, merge keys, tags) that make files harder for people and agents to read on their own. Lint must point at exact lines.

## Decision

- Files are parsed as YAML 1.2 with the core schema, using the `yaml` library (eemeli/yaml), which keeps source ranges for every node and rejects duplicate keys.
- Anchors, aliases, merge keys (`<<`), explicit tags and multi-document files are rejected (RADD101). Reuse happens through domain types.
- Layout: `dictionary.yaml`; `entities/**/*.yaml` (`entity:`); `types/**/*.yaml` (`domainType:`); `lookups/**/*.yaml` (`lookup:`); `validators.yaml`, `calculators.yaml`, `functions.yaml` (maps by name); `i18n/<locale>.yaml` or `i18n/<locale>/**/*.yaml` (flat key-to-text maps). Folders may be nested.
- File names carry no meaning: the name comes from the top-level key, so renaming or moving a file never changes the build. Lint warns (RADD305) when the file name is not the kebab-case form of the name. Other `.yaml` files and `.yml` files are ignored with a warning (RADD104); non-YAML files such as `AGENTS.md` are ignored silently.
- `dictionary.yaml` carries `formatVersion: 1`, the RADD format the files are written in. The dictionary's own version is the content hash, which exists only in the canonical JSON (ADR-0028).
- Relationships are declared as `{ kind: manyToOne | oneToMany | manyToMany, entity, foreignKey | through }`, so editors can autocomplete `kind` and the schema can give one clear error per mistake.

## Alternatives considered

- **YAML 1.1 (the `js-yaml` default).** Silently turns lookup codes like `N` and `NO` into booleans.
- **Allowing anchors and merge keys.** Shorter files, but a field's meaning would depend on text elsewhere in the file.
- **A `version` property in `dictionary.yaml`.** Would duplicate, and could contradict, the content hash.
- **Relationships keyed by kind (`oneToMany: OrderLine`).** Proposed first; replaced by an explicit `kind` for better editor support.

## Consequences

- Line and column are available for every diagnostic.
- Authors repeat small things (for example `required: true`) instead of aliasing them.
