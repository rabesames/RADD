# ADR-0022: Localized text in per-locale YAML files using ICU MessageFormat

- Status: Accepted
- Date: 2026-10-26
- Deciders: Rommel

## Context

Every label, hint, lookup label and validation message must be translatable, render the same in every runtime, and be reviewable in pull requests. v1 ships with full support for multiple locales.

## Decision

- All user-facing text lives in `i18n/<locale>.yaml` (a locale may be split over `i18n/<locale>/*.yaml`) as a flat map of stable message keys to ICU MessageFormat text.
- Resolution order for a constraint message: field-specific key, then domain-type key, then framework default (`radd.required`).
- A missing key in the default locale fails lint; a missing key in another locale falls back to the default locale and is reported as a warning.
- The API picks the locale from `Accept-Language`; the client requests metadata for one locale at a time. AI agents may draft missing translations as a pull request for human approval.

## Alternatives considered

- **Resource files per runtime (.resx, JSON bundles).** Duplicates text per stack.
- **Simple `{name}` substitution.** No plurals or selects; ICU is supported in both .NET and JavaScript.

## Consequences

- Lint parses every message as ICU (RADD504).
- How keys are derived and resolved at build time is set out in ADR-0030.
