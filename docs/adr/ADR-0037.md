# ADR-0037: Primary keys can be generated as identity or uuid

- Status: Accepted
- Date: 2026-10-26
- Deciders: Rommel

## Context

Most tables use a surrogate key that callers do not supply: an auto-increment integer assigned by the database, or a GUID assigned by the application. The dictionary must say which, so EF, the API, the client and `radd db diff` all treat the key the same way.

## Decision

- A primary key field may declare `generated`:
  - `identity` (integer or long): the database assigns the value on insert. The long form `{ kind: identity, seed, increment, noReuse }` sets the first value and step where the database supports them (SQL Server, Postgres), and `noReuse: true` emits SQLite `AUTOINCREMENT` so keys of deleted rows are never reused.
  - `uuid` (guid): the application assigns a GUID before insert (EF's GUID generator; sequential GUIDs on SQL Server).
  - Omitted: the caller supplies the value.
- A generated key is always read-only: UIs show it but never offer it for editing, it is left out of create payloads, and the API returns the generated value after insert.
- The canonical form writes `generated` as an object with defaults (`seed: 1`, `increment: 1`, `noReuse: false`) and sets `readOnly: always`.
- Lint (RADD213): only primary key fields can be generated; `identity` only on integer or long, at most one per entity; `uuid` only on guid; no `default` or `computed` on a generated key, and `readOnly` must be `always` if given. Lint warns (RADD214) when SQLite is enabled and a custom seed or increment would be ignored.
- `radd db diff` classifies adding or removing identity on an existing column as destructive.

## Alternatives considered

- **`default: { expression: "newGuid()" }` and `readOnly: always` for GUID keys.** Works for uuid but not identity, says less about intent, and leaves EF and the API to infer generation.
- **Database sequences as a separate concept.** More general, but not portable to SQLite; can be added later.

## Consequences

- The example uses `generated: uuid` for Customer, Order and OrderLine, and `generated: identity` for Province.
- `newGuid()` stays available for non-key defaults (ADR-0031).
- Stage 3 maps `identity` to `ValueGeneratedOnAdd()` plus provider identity settings, and `uuid` to EF's GUID value generator.
