# ADR-0014: Handling of read-only fields in a write payload is deferred past v1

- Status: Accepted
- Date: 2026-10-26
- Deciders: Rommel

## Context

When a client sends a value for a read-only or computed field, the API could reject the request with 422 or silently ignore the value. Both are reasonable, and teams differ.

## Decision

The choice is deferred past v1. It will become a dictionary setting (reject or ignore), and computed fields will follow the same setting.

## Alternatives considered

- **Always reject.** Strict, but breaks clients that send whole objects back.
- **Always ignore.** Lenient, but hides client bugs.

## Consequences

- v1 runtimes must document their interim behavior, and stage 4 picks one consistently for both the endpoint filter and the interceptor.
