# ADR-0025: Repository layout and TypeScript tooling

- Status: Accepted
- Date: 2026-10-26
- Deciders: Rommel

## Context

Stage 1 sets up a monorepo holding the JSON Schema, the TypeScript core and CLI, the .NET solution, conformance vectors, the example and the docs. The tooling must work from a fresh clone on Windows and Linux with `npm install` and `npx radd`.

## Decision

- Layout: `schema/v1`, `packages/core` (`@radd/core`), `packages/cli` (`@radd/cli`, bin `radd`), `dotnet` (`RADD.slnx`), `conformance`, `examples/acme-orders`, `scripts`, `docs`, `docs/adr`.
- npm workspaces; TypeScript 7 in strict mode, ESM only (`"type": "module"`, `module: nodenext`), project references built with `tsc -b`. The root `prepare` script builds on `npm install`.
- Vitest for tests, Biome for formatting and code lint (Markdown and YAML are excluded: Biome rewrites tables and code blocks in docs, and would reflow the flow mappings dictionary authors write), `commander` for CLI parsing.
- .NET: `RADD.Core`, `RADD.EntityFrameworkCore`, `RADD.AspNetCore` on net10.0 and `RADD.Generators` on netstandard2.0 (required for Roslyn generators); nullable and warnings-as-errors on; central package management.
- `.gitattributes` normalizes text files to LF, so hashes, snapshots and ADR checks do not depend on the checkout's line endings.

## Alternatives considered

- **pnpm or Yarn.** Extra tooling to install; npm workspaces are enough here.
- **TypeScript 6.** TypeScript 7's `tsc -b` with project references works, so the latest stable release was kept.
- **ESLint with typescript-eslint and Prettier.** Two tools and more configuration for the same result.
- **Running TypeScript directly with Node's type stripping.** Workspace packages resolve through `node_modules`, where Node refuses to strip types.

## Consequences

- A fresh clone needs only Node and `npm install`; the .NET SDK is needed only for `dotnet build`.
- Schemas are read at run time from the repository's `schema/v1`; publishing `@radd/core` will require bundling them into the package.
