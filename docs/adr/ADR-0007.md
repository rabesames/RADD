# ADR-0007: Display and edit metadata on fields, with text in i18n and ICU formats

- Status: Accepted
- Date: 2026-10-26
- Deciders: Rommel

## Context

UIs and reports need more than a label to present a field: a short label for narrow columns, a hint, a placeholder, how to render a value (grouping, decimals, dates) and how to accept it while editing. Without this in the dictionary, every screen and report re-implements it, which is the duplication RADD exists to remove.

## Decision

- Every field can carry `displayLabel`, `shortLabel`, `displayHint` and `placeholder`. They are user-facing text, so they live in `i18n/` under keys derived from the path (`customer.creditLimit.displayLabel`); a field may name a different key, for example when two fields share a label. `label` and `help` are renamed to `displayLabel` and `displayHint`.
- `displayHint` is HTML limited to an allowlist (`b`, `strong`, `i`, `em`, `br`, `p`, `ul`, `ol`, `li`, `code`, and `a` with an `https` link). Lint rejects anything else; the client sanitizes again and also exposes a plain-text version. Scripts, styles, event handlers and images are never allowed.
- `displayFormat` (how a stored value is rendered) and `editFormat` (how it is shown and typed while editing, and parsed back) use ICU patterns, so every runtime renders the same: kinds `number`, `percent`, `currency`, `date`, `time`, `datetime`, `boolean`, `text` for display, and `number`, `mask`, `date`, `time`, `datetime`, `text` for editing. Grouping and decimal symbols follow the viewer's locale unless `symbols` fixes them. Domain types can define formats that their fields inherit.
- `min` and `max` are inclusive bounds on numeric fields, enforced by the API, checked by the client, a CHECK constraint where the database supports one, and available to UIs.
- All of it is presentation only: the API stores and returns raw values.

## Alternatives considered

- **Leave presentation to each UI.** Repeats formatting and labels on every screen and report.
- **Formats as runtime-specific strings (.NET format strings, `Intl` options).** Not portable; ICU is the common ground.
- **Plain-text hints only.** Too limited for emphasis and links; an allowlist keeps HTML safe.

## Consequences

- Lint checks the hint HTML in every locale (RADD506), the ICU pattern syntax (RADD704), that a format kind suits the field type (RADD212), and that `min` and `max` fit the type, precision and scale (RADD211).
- `@radd/client` gains `radd.format` and `radd.parse` (stage 6), and .NET offers the same for reports.
- Neither JavaScript's `Intl` nor .NET format strings take ICU patterns directly, so each runtime needs a pattern interpreter for the supported subset, proven by conformance vectors.
