# ADR-0009: A Node/TypeScript CLI core with stack plugins in each stack's language

- Status: Accepted
- Date: 2026-10-26
- Deciders: Rommel

## Context

One `radd` command must lint, build, diff, generate code, initialize projects and diff databases for several stacks. Some of that work is stack-neutral; some needs a framework's own tooling (EF Core for `db diff`, Roslyn-friendly C# for code generation).

## Decision

- The core is TypeScript on Node. It does the stack-neutral work (loading and linting the dictionary, semantic diff, docs, the MCP server, prompts) and reuses the same loader, JSON Schema and expression evaluator as `@radd/client`, so `radd validate` behaves exactly like the client.
- Stack-specific work runs in a plugin written in that stack's language (the .NET plugin is a .NET tool hosting EF Core). The core calls a plugin as an executable and exchanges JSON over stdin and stdout.
- Every command has a flag for every question, `--yes` to accept defaults, `--json` output and a non-zero exit code on failure. No command changes a database.
- Distributed through npm (`npx radd`), from the git repo for now; plugins install through their own ecosystem.

## Alternatives considered

- **A .NET CLI.** Natural for the first backend, but the front end and later Java/Python stacks would need .NET, and the client's TypeScript evaluator could not be reused.
- **One binary per stack.** Duplicates the stack-neutral work and lets behaviors drift.
- **In-process plugins (npm packages).** Cannot host EF Core or Hibernate.

## Consequences

- Node is required wherever `radd` runs; it is already required for the React front end.
- The plugin protocol is a public contract (stage 8).
