# ADR-0005: CEL for expressions, with a declared subset, custom functions and named server validators

- Status: Accepted
- Date: 2026-10-26
- Deciders: Rommel

## Context

Conditional rules, cross-field rules, lookup filters and application-computed fields need an expression language that runs identically in TypeScript and .NET (and later Java and Python), can be checked at lint time, always terminates, and is safe to evaluate on the server.

## Decision

- Expressions are written in CEL (Common Expression Language). Variables are the record's fields by name, `row` for the candidate row in a lookup filter, and `ctx` for server-supplied values (`ctx.today`, `ctx.locale`).
- `dictionary.yaml` declares the CEL extensions allowed (`expressions.extensions`); anything outside the subset fails `radd lint`.
- `functions.yaml` declares project-specific functions (name, signature, description, client-safe or server-only). The framework ships `isBlank` and decimal-safe `dec.add`, `dec.sub`, `dec.mul`, `dec.eq`, `dec.round`.
- Decimal arithmetic and equality use the `dec.*` functions; lint warns on raw arithmetic over decimal fields. Regexes use RE2 syntax and lint validates them.
- Anything that needs the database, business calendars, cross-record aggregates or complex decisions is a named server validator (`validators.yaml`) or calculator, not an expression. Startup fails if a declared validator has no implementation; the CLI fails if an entity references an undeclared one.
- The .NET and TypeScript libraries are chosen in stage 2 by pass rate on the official cel-spec conformance corpus, custom-function support and type checking.

## Alternatives considered

- **JSONLogic.** Loose semantics, no type checking and a small set of built-in functions.
- **JavaScript or C# snippets.** Not portable across runtimes, and unsafe to evaluate.
- **A custom expression language.** Every runtime would need a new parser and evaluator with no external conformance corpus.

## Consequences

- Each runtime depends on a CEL library and implements the RADD built-ins and the project's custom functions as extensions.
- Lint can type-check expressions against declared field types once the library is chosen; until then, stage 1 lint checks function references lexically (ADR-0036).
