# ADR-0002: The dictionary is a folder of YAML files validated by JSON Schema

- Status: Accepted
- Date: 2026-10-26
- Deciders: Rommel

## Context

The dictionary is the single source of truth for every layer, lives in the application's repo, changes only through pull requests, and is written by people and by AI agents. It must diff cleanly, merge without conflicts on busy teams, and be checkable by machines.

## Decision

- The dictionary is a folder of YAML files (`dictionary.yaml`, `types/`, `lookups/`, `entities/` with one file per entity, `validators.yaml`, `calculators.yaml`, `functions.yaml`, `i18n/`), validated against a published, versioned JSON Schema.
- Tools merge the folder into one canonical JSON document with a content hash, which every runtime consumes and which serves as the dictionary version.
- Fields use logical types, never database types; each database adapter maps them.

## Alternatives considered

- **JSON files.** Machine-friendly but noisy to read and write by hand, with no comments.
- **One large file.** Every change touches the same file, causing merge conflicts and large diffs.
- **A database or admin UI as the source.** Not repo-native: changes would bypass pull requests, review and CI.
- **Code (C# attributes or a TypeScript DSL).** Ties the dictionary to one stack and makes it hard for other runtimes and agents to read.

## Consequences

- Editors, the CLI and agents validate against the same schema.
- Runtimes never parse YAML themselves at run time; they load the canonical JSON.
- The format must be specified independently of any language, and changes to it are versioned (`formatVersion`).
