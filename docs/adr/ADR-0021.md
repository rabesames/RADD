# ADR-0021: Validation results as RFC 9457 ProblemDetails, with error, warning and info severities

- Status: Accepted
- Date: 2026-10-26
- Deciders: Rommel

## Context

The API and the client must report validation results the same way, so UI code handles both identically, and some rules should warn rather than reject.

## Decision

- The API returns RFC 9457 ProblemDetails (`type: urn:radd:problem:validation`, status 422) extended with `dictionaryVersion` and a `results` list. Each result has `path`, `code`, `severity`, `message` (resolved in the request's locale) and optional `params`. The client-side validator produces the same shape.
- Severities: **error** rejects the save; **warning** rejects the save until the client resubmits with the codes acknowledged in `RADD-Acknowledge`; **info** lets the save proceed and returns the message.
- `code` and `params` are always returned so a client can re-render the message in another locale.

## Alternatives considered

- **ASP.NET Core's default `ValidationProblemDetails`.** Field-to-messages map only: no codes, severities or params.
- **Two severities only.** No way to express "questionable but allowed with confirmation".

## Consequences

- Every rule has a stable code; for rules with an explicit message the code defaults to the message key (ADR-0030).
- Warnings require a resubmission round trip.
