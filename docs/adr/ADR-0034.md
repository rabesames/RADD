# ADR-0034: ADR enforcement through a required CI check, with the merge as approval

- Status: Accepted
- Date: 2026-10-26
- Deciders: Rommel

## Context

The plan asks for `CODEOWNERS` to make Rommel a required reviewer for `docs/adr/`. Pull requests are opened under Rommel's own GitHub account, and GitHub does not let an author approve their own pull request, so requiring code-owner review would block every pull request.

## Decision

- `.github/CODEOWNERS` assigns `/docs/adr/` to `@rabesames`, which documents ownership and requests his review.
- "Require review from Code Owners" is not enabled. Instead, the ADR check job in CI is a required status check on `main`, and Rommel's merge is the approval.
- The ADR check (`scripts/check-adrs.mjs`) fails a pull request that deletes an ADR, changes a Superseded, Obsolete or Rejected ADR, or changes a Hardened ADR other than moving its status to Superseded or Obsolete with a valid Superseded-by line. It also fails if the index and the ADR files disagree.

## Alternatives considered

- **Required code-owner review.** Unsatisfiable while the author and the code owner are the same account.
- **A separate machine account for Claude's pull requests.** Makes code-owner review possible, but adds an account and credentials to manage; can be revisited.

## Consequences

- Nothing technically stops Rommel from merging a pull request that hardens an ADR it should not; the gate is his review.
- The branch-protection setting has to be made in the repository settings.
