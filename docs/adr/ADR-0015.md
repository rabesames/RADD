# ADR-0015: How users see and acknowledge warnings is left to the component layer

- Status: Accepted
- Date: 2026-10-26
- Deciders: Rommel

## Context

Warnings block a save until the client resubmits with the warning codes acknowledged. Something has to show them to the user and collect the acknowledgment, but v1 is headless.

## Decision

The client logs every validation error and warning through its pluggable logger and returns results in the API's shape. How users see and acknowledge errors and warnings is decided by the future UI component layer, not by `@radd/client`.

## Alternatives considered

- **A built-in dialog or toast.** Would tie the client to a UI framework.

## Consequences

- Applications in v1 render results themselves and send `RADD-Acknowledge` with the codes the user accepted.
