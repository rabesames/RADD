# ADR-0023: A shared conformance suite, not shared code, keeps runtimes consistent

- Status: Accepted
- Date: 2026-10-26
- Deciders: Rommel

## Context

RADD runs in several languages (TypeScript and C# now, Java and Python later) and against several databases. They cannot share an implementation, but must behave identically.

## Decision

- A language-neutral folder of test vectors (`/conformance`) defines the expected behavior: dictionary in, canonical JSON out; dictionary plus record in, results out (codes, severities, paths, messages per locale); expression evaluation; conditional state; lookup filtering; and per database, the expected DDL after a diff from a known schema.
- The TypeScript and .NET runtimes run the suite in CI from v1. A new backend or database adapter ships only when it passes.

## Alternatives considered

- **One implementation compiled to every platform (for example WebAssembly).** Would fight each framework's native features (ADR-0003, goal 3 of the spec).
- **Documentation only.** Behavior drifts without executable checks.

## Consequences

- Every behavior added in a stage adds vectors.
- The canonical form and hash must be reproducible from a published algorithm (ADR-0028).
