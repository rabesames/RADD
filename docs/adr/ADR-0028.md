# ADR-0028: Canonical form and version hash

- Status: Accepted
- Date: 2026-10-26
- Deciders: Rommel

## Context

Every runtime consumes one canonical JSON document, and its hash is the dictionary version: it is sent as `RADD-Version`, used in ETags and invalidates client caches. The hash must change when meaning changes and only then, and other languages must be able to reproduce it.

## Decision

- `radd build` runs lint and refuses to build if there are errors.
- **Defaults are explicit** in the canonical document: `required`, `readOnly` (always `always` for computed and generated fields), `generated` options, edit-format settings, `cache`, `search`, `active`, `persisted`, `stored`, `audit`, `softDelete`, `onDelete`, severities, `dbName` and `apiName` (ADR-0029), index names (`IX_`/`UX_<Table>_<Columns>`), resolved message keys, and `primaryKey` as an array. Writing a default out or leaving it implicit gives the same hash.
- **Normalization:** durations become seconds (`10m` becomes `ttlSeconds: 600`); a field's `unique: true` becomes a unique index identical to an explicit one; a reference-table lookup gets an explicit `references` (foreign key); set-like arrays (`tags`, `dependsOn`, `extensions`, supported locales, databases) are sorted and de-duplicated; other arrays keep their order; expressions are trimmed.
- **Domain types are expanded** into each field: field values win; rules and validators are concatenated domain first; `domain` is kept for reference.
- **Field order is meaningful.** Each entity has a `fieldOrder` array in declaration order (it sets column, property and default form order), so reordering fields changes the hash; reordering properties inside a definition does not.
- **Hash:** SHA-256 over the RFC 8785 JSON Canonicalization Scheme (JCS) serialization of the document without its `version` property, written as `version: "sha256:<64 hex>"`. File names, comments, whitespace, key order and line endings do not affect it; descriptions and message text do.
- **Output:** pretty-printed, key-sorted JSON with two-space indent, LF and a trailing newline, written to `<dir>/../.radd/dictionary.json` unless `--out` is given.

## Alternatives considered

- **Hash the YAML bytes.** Changes with whitespace, comments, file names and key order.
- **Hash only "semantic" properties (exclude descriptions and messages).** Messages are served to clients, so they must invalidate caches; descriptions are cheap to include and keep the rule simple: any value change is a new version.
- **An ad hoc canonical JSON.** JCS is a published standard with implementations in other languages.
- **Sorting fields alphabetically with no order record.** Loses the column and form order authors chose.

## Consequences

- Whitespace inside a CEL expression still changes the hash until expressions are normalized with the stage 2 parser.
- Numbers go through IEEE-754 doubles, so literal defaults beyond about 15 significant digits lose precision (use string types for such values).
- A change to the build logic can change every hash; the canonical snapshot test and conformance vectors make such changes visible in review.
