# ADR-0029: Logical, database and API names for entities and fields

- Status: Accepted
- Date: 2026-10-26
- Deciders: Rommel

## Context

The spec did not say how fields map to columns or JSON properties, and only gave entities a `table`. Existing databases have their own naming; APIs have theirs; expressions, message keys and generated code need one stable name.

## Decision

- Every entity and field has three names:
  - **Logical name:** the YAML key. Entities PascalCase (`OrderLine`), fields lowerCamelCase (`countryCode`). CEL expressions, message keys and generated C# use it.
  - **`dbName`:** the table or column name. Defaults to TitleCase of the logical name (`Customer`, `CountryCode`), never pluralized.
  - **`apiName`:** the JSON property name and `/_radd` route segment. Defaults to camelCase (`orderLine`, `countryCode`).
- Both can be overridden per entity and field (`dbName: Countries`, `dbName: IsoCode`); the canonical JSON always states both.
- `dbName` replaces the spec's `table:`. Database-computed SQL refers to columns by `dbName`.
- Lint (RADD303) requires plain identifiers and rejects two fields of an entity, or two entities, with the same `dbName` or `apiName` ignoring case.

## Alternatives considered

- **snake_case tables and columns.** Proposed first; Rommel chose TitleCase database names.
- **Column name equal to the field name.** Would force database naming onto the dictionary's logical names.
- **Pluralized table names.** Needs an English pluralizer and guesses wrong for some names; use `dbName` when a plural is wanted.

## Consequences

- An existing database can be described without renaming anything.
- TitleCase identifiers are case-sensitive in Postgres and must be quoted there; the Postgres adapter will quote all identifiers.
- Index default names use column `dbName`s.
